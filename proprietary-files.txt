# pdx256 리커버리 복호화용 blob
#
# 출처가 pdx256 순정이 아니라 pineapple(SM8650) TWRP 입니다. 이유:
#
# pdx256 자신의 vendor blob 으로는 TZ 핸드셰이크가 거부됩니다:
#   SmcInvoke_MinkDescriptor: Failed to open invoke driver, errno = 13
#   SmcInvoke_TZCom: TZCom_getRootEnvObject ret=1
#   ListenerMngr: Error -1 getting clientEnv
# 파일 권한도 SELinux 도 아닙니다 (셸에서는 /dev/smcinvoke 가 정상 오픈되고
# setenforce 0 으로도 동일하게 실패). 반면 pineapple TWRP 의 더 오래된 blob 은
# 같은 /dev/smcinvoke 와 같은 리스너 10개를 쓰면서 이 기기에서 실제로 동작합니다.
# QTI TZ 인터페이스가 기종 간 호환되는 덕분입니다.
#
# 이 파일들은 recovery/root/system/{bin,lib64} 에 직접 커밋되어 있습니다.
# TWRP 램디스크 조립이 device tree 의 recovery/root 를 통째로 복사하므로
# PRODUCT_COPY_FILES 규칙이 필요 없고, ELF prebuilt 검사도 우회합니다.
#
# 위치가 /vendor 가 아니라 /system 인 것도 의도적입니다. 리커버리 링커는
# /system/${LIB} 만 검색하고, init.recovery.qcom_decrypt.rc 의 LD_LIBRARY_PATH 는
# /vendor/lib64 를 먼저 봅니다 -- pdx256 의 옛 blob 을 /vendor 에 남겨두면
# pineapple 것을 가려버리므로 전부 제거했습니다.
